  • 공모전 SDK는 Vehicle, NaviHelper, TextToSpeech, SpeechToText, FusedLocation 다섯 개입니다. 이 가운데 지금 신청 없이 바로 쓸 수 있는 것은 Vehicle State(차량 상태 조회)와 NaviHelper뿐입니다. TextToSpeech, SpeechToText, FusedLocation, Vehicle Control(차량 제어)은 "준비 중(Coming Soon)" 상태입니다(2.1절).
  • 공개 ADAS·차량 데이터로 졸음이나 부주의를 직접 알 수 없습니다. 운전자 주의 경고(DRIVER_ATTENTION), 차선 유지(LKA), 전방 충돌(FCA) 같은 경고등 정보와 AAOS의 운전자 졸음·주의 분산·차선 이탈 상태는 모두 signature|privileged 권한이라 서드파티 앱이 받을 수 없습니다. 실내 카메라와 생체 신호 API도 없습니다(2.3절, 2.7절, 2.8절).
  • 좌석별 탑승 여부(getCurrentSeatOccupancy), 좌석별 안전벨트, 도어·창문, 실내 온도, EV 배터리 잔량, 현재 주행 시간은 일반 권한으로 읽을 수 있고 에뮬레이터 Virtual Console에서 재현됩니다(2.3절).

  • NaviHelper는 위치, 목적지, 남은 거리·시간, 도착 시 예상 배터리, 충전 계획, 주의 구간, 제한 속도(1초 주기)를 주고 경로·경유지를 설정할 수 있지만, 휴게소·졸음쉼터 검색 API는 없습니다(2.4절).
  • 주행 중에는 동영상·게임·브라우저 앱을 쓸 수 없고, 앱은 CarUxRestrictions에 맞춰 기능을 줄여야 합니다(2.9절).
  • 현실 문제: 고속도로 사망자의 약 70%가 졸음·주시태만으로 집계되었고, 졸음운전 치사율은 전체 사고의 약 2배입니다(3.1절). 충전 앱의 "사용 가능" 표시가 실제와 다른 경험은 20.6%였습니다(3.3절). 뒷좌석 아이와의 상호작용은 휴대전화 상호작용의 12배 빈도로 관찰되었습니다(3.6절).
  • 후보 판정(4장, 5장)은 세 후보 모두 "부분"입니다. 이 보고서는 아이디어를 고르지 않습니다.

  • 동승자 엔터테인먼트: 주행 중 화면 콘텐츠는 불가능합니다. 위치·경로 기반 음성 콘텐츠는 음성 SDK가 준비 중입니다.

Android 표준 API인 CarPropertyManager.getPropertyList는 대조 대상에서 빠졌습니다.
  • AAOS 표준 차량 프로퍼티의 권한은 Android 공식 레퍼런스(developer.android.com/reference/android/car/VehiclePropertyIds)를 2026년 10월 23일에 내려받은 본으로 확인했습니다. 로그인 상태나 접속 환경에 따라 이 주소가 Google 로그인 화면으로 이동할 수 있습니다.
  • 현실 문제는 정부·공공기관 통계, 언론 보도, 연구 논문, 소비자 조사, 커뮤니티 글을 찾아 각 주장 옆에 출처를 붙였습니다. 열어 보지 못했거나 수치를 대조하지 못한 항목은 "확인 못 함"으로 적었습니다.
  • 이 보고서는 아이디어를 고르지 않습니다. 근거와 판정만 정리합니다.
  • 판정 기준: "가능"은 공모전에서 지금 쓸 수 있는 공개 API(사용 가능 상태 SDK 또는 normal·dangerous 권한의 AAOS 프로퍼티)로 필요한 데이터를 모두 얻는 경우입니다. "부분"은 일부 데이터만 얻거나 준비 중 SDK에 기대는 경우입니다. "불가"는 핵심 데이터가 signature|privileged 권한 뒤에 있거나 공개 API가 없는 경우입니다.

이 장의 API 이름은 Pleos Playground 공개 문서의 API Reference 표기를 그대로 옮겼습니다. API Reference 본문은 브라우저에서 스크립트로 그려지는 방식이어서, 공개 문서 사이트가 배포하는 문서 번들에서 1,866개 API 페이지 원문을 추출해 대조했습니다. 각 행의 URL은 사람이 열어 볼 수 있는 해당 API 페이지 주소입니다. 문서 기준 버전은 Vehicle SDK v2.3.2, NaviHelper v3.0.5, TextToSpeech v3.3.1, SpeechToText v3.3.1, FusedLocation SDK v1.1.3이며 릴리스일은 2026년 10월 19일입니다(document.pleos.ai/docs/pleos-only/release-note/sdk-261015).

2.1SDK 목록과 공모전 사용 가능 상태

공모전이 안내하는 SDK는 Vehicle SDK, NaviHelper SDK, TextToSpeech SDK, SpeechToText SDK, FusedLocation SDK 다섯 개입니다(appdevchallenge.auto-hmg.io/faq, "어떤 SDK와 API를 쓸 수 있나요?"; appdevchallenge.auto-hmg.io/guide/development, "Pleos Connect SDK"). 공모전 FAQ는 "각 SDK의 현재 제공 상태와 사용 조건은 SDK 문서 페이지에서 확인"하라고 안내합니다. Playground 문서의 SDK 사용 신청 절차는 각 SDK의 상태를 다음과 같이 밝힙니다(document.pleos.ai/docs/pleos-only/create-my-project, "SDK 사용 신청").

Vehicle State와 Vehicle Control의 경계는 문서에 API 단위로 적혀 있지 않습니다. 퍼미션 체계가 조회용 CAR_* 와 제어용 CONTROL_CAR_* 로 나뉘어 있으므로(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle-permission, "퍼미션 종류"), 이 보고서는 Vehicle State를 CAR_* 조회·구독 API로, Vehicle Control을 CONTROL_CAR_* 설정 API로 추정합니다. 이 대응은 추정이며 문서로 확인 못 함입니다.

에뮬레이터 개발은 신청 상태와 별개로 문서화되어 있습니다. TextToSpeech와 SpeechToText의 ON_DEVICE 모드는 앱 등록 없이 동작한다고 문서에 적혀 있습니다(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/intro, "음성 합성 모드"; document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/intro, "음성 인식 모드"). 준비 중 상태의 SDK가 에뮬레이터에서 실제로 호출되는지는 로그인과 실행이 필요해 확인 못 함입니다.

Pleos App Market 출시 단계에서는 App Market과 사전 협의해 승인받은 Vehicle SDK 퍼미션만 선언할 수 있습니다. 승인되지 않은 퍼미션을 선언한 앱은 심사를 통과할 수 없습니다(document.pleos.ai/docs/pleos-only/distribute/app-review-guide/review-functionality-performance-stability, "SDK·API 사용 심사"). 공모전 2차 PT는 에뮬레이터 구동 화면 시연을 인정합니다(appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000006, "2. 심사 및 시상·현장 시연 관련 유의사항").

2.2공통 개발 환경

  • 최소 Android API 28, Gradle 8.0 이상, Java 또는 Kotlin을 사용합니다. 에뮬레이터는 Pleos Connect Emulator 2.1.0이며 Android Studio SDK Manager에 업데이트 사이트를 추가해 Android API 34 시스템 이미지로 설치합니다(document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator, "소프트웨어 개발 환경", "Emulator를 Android Studio에 추가하기").
  • Pleos Connect Virtual Console은 에뮬레이터의 8088 포트를 포워딩한 뒤 PC 브라우저에서 차량 상태를 바꾸는 도구입니다(document.pleos.ai/docs/connect/guide/getting-started/application-development/use-vehicle-emulator, "Pleos Connect Virtual Console 실행 방법").
  • Vehicle SDK 호출은 IPC이므로 capability·get·set 결과가 onComplete·onFailed 비동기 람다로 돌아옵니다. register* 함수는 리스너를 등록해 상태 변화를 구독합니다(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/intro, "진입점과 도메인 구조").
  • 갱신 주기: Vehicle SDK 문서는 Hz나 주기 값을 적지 않습니다. register* 리스너는 "property updates"를 받는다고만 적혀 있어, 고정 주기는 확인 못 함입니다. NaviHelper의 onCurrentRoadSpeedLimit만 "등록 후 매초 수신"으로 주기가 명시되어 있습니다(2.4절).
  • 차량 모델마다 지원 API가 다르며 checkXXXCapabilities로 지원 여부를 확인해야 합니다(document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/api-compatibility-availability, "Pleos Connect SDK API 호환성").

2.3Vehicle SDK

진입점은 Vehicle 클래스입니다. 이 클래스는 initialize(), release()와 다음 도메인 획득 함수 getBrake(), getCarInfo(), getDisplay(), getDoor(), getDrivingMode(), getEvBattery(), getFuel(), getHVAC(), getLight(), getOdometer(), getSafety(), getSeat(), getSideMirror(), getSteeringWheel(), getTire(), getToll(), getTurnSignal(), getWindow(), getWiper()를 제공합니다(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle/vehicle/entry). 아래 표의 보호 수준은 각 API 페이지의 "Permission: ... (protection level: ...)" 표기입니다. normal은 일반 앱이 선언만으로 받는 수준이고, signature|privileged는 플랫폼 서명이나 시스템 권한 앱만 받는 수준입니다.

Virtual Console 열은 Virtual Console 사용 가이드의 카드 목록 기준입니다(document.pleos.ai/docs/pleos-only/app-test-guide/virtual-console-guide, "Emulation Controls 사용 방법"). 기어(P, R, N, D)는 Virtual Console에서 바꿀 수 있습니다. Vehicle 클래스 설명의 예제 코드에는 vehicle.getGear(), registerGearSelection, GearSelectionListener가 나오지만, 같은 페이지의 함수 목록과 API Reference의 도메인 페이지에는 Gear가 없습니다(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle/vehicle/entry). Vehicle SDK의 기어 API 제공 여부는 확인 못 함이며, 문서가 확실히 안내하는 경로는 AAOS 표준 프로퍼티 GEAR_SELECTION입니다(2.7절).

조향각 주의점: getCurrentSteeringWheelAngle의 값은 "front-wheel steering angle"입니다. 문서는 이 값이 "does not represent the rotation angle of the steering wheel"이라고 명시합니다(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/steering-wheel/get-current-steering-wheel-angle). Virtual Console 카드는 같은 값을 "스티어링 휠 각도 -540~540도"로 설명해 표현이 다릅니다.

경고등(Telltale) 상세: TelltaleType은 경고등 종류를 나열한 열거형입니다. 여기에는 DRIVER_ATTENTION, FCA, LKA, LFA, LCA_LEFT, LCA_RIGHT, ICC, OVER_SPEED, SEAT_BELT, DOOR_OPEN, TPMS, CHILD_PRESENCE_DETECTION_OFF, LOW_EV_BATTERY, LOW_FUEL, ENGINE, MASTER_WARNING 등이 있고, TelltaleData는 type, state(OFF, ON, BLINK), color, priority, warningCount를 담습니다(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.constant.telltale/telltale-type/entry 및 document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api.model.telltale/telltale-data/entry). 그러나 이 데이터를 받는 getTelltalesInfo, registerTelltales는 PRIVATE_CAR_SAFETY(signature|privileged)를 요구합니다. getTelltalesInfo 페이지는 어노테이션에 CAR_SAFETY, 설명에 PRIVATE_CAR_SAFETY(signature|privileged)를 함께 적어 표기가 서로 다릅니다. registerTelltales와 checkTelltalesCapabilities는 어노테이션과 설명 모두 PRIVATE_CAR_SAFETY입니다. 따라서 운전자 주의 경고(DAW) 점등 여부는 열거형에는 있지만 서드파티 앱이 받을 수 없는 것으로 판단합니다.

삭제된 API: Vehicle SDK v2.3.2에서 VehicleSpeedListener와 onSpeedUpdated가 삭제되었습니다(document.pleos.ai/docs/pleos-only/release-note/sdk-261015, "Shutdown API").

2.4NaviHelper SDK

NaviHelper는 Pleos Connect 내장 내비게이션과 연동하는 SDK입니다. 진입점은 NaviHelper(context)이며 initialize(), initialize(onConnected, onFailed), addListener(), removeListener(), release()를 제공합니다(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/navi-helper/ai.pleos.playground.navi.helper/navi-helper/entry). 내비게이션이 탑재된 차량에서만 전체 호환됩니다(document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/api-compatibility-availability). 공모전 상태는 "사용 가능"입니다(2.1절).

NaviHelperEventListener는 다음 이벤트를 제공합니다. onCurrentLocationInfo, onCurrentRoadSpeedLimit(등록 후 매초 수신), onCameraAlert, onCautionPointInfo, onTBTInfo, onDrivingInfo, onTripInfo, onRouteStateInfo, onNavigationStatus, onRouteStarted, onRoutingCompleted, onReRouteEnded, onRouteCancelled, onRouteOptionChanged, onDestinationInfo, onDestinationChanged, onDestinationArrived, onWayPointInfo, onWaypointChanged, onWayPointArrived, onBookmarkInfo, onBookMarkChanged, onRecentDestinationInfo, onChargerOperatorInfo, onError(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/navi-helper/ai.pleos.playground.navi.helper.listener/navi-helper-event-listener/entry).

주요 데이터 필드는 다음과 같습니다(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/navi-helper/ai.pleos.playground.navi.data/entry).

  • CurrentLocationInfo: latitude, longitude, heading, address, routeId, currentRouteIndex
  • DestinationInfo: name, address, remainDistance, remainTime, tollFare, poiId
  • TripInfo: distance(m), eta(초), estimatedSocAtDest(도착 시 예상 배터리 %), energyConsumption(Wh), summary(TripSummary: trafficConditions, routePoints)
  • DrivingState: duration, distance, remainDestinationChargingValue, isChargingStation, isRecommendedChargingStation, maxChargingPower, targetSoc, chargerCount, chargingPlan(duration, startSoc, endSoc)
  • CameraAlert: type, speedLimit, remainDistance, sectionAvrSpeed, isOverSpeed, isOverSectionAvrSpeed
  • CautionPoint: type(SPEED_BUMP, SCHOOL_ZONE, ACCIDENT_PRONE_AREA, FOG_AREA, FALLING_ROCK_AREA, DOWNHILL_CAUTION_AREA, WILDLIFE_CROSSING 등), remainDistance
  • RouteStateInfo.trafficStatus: TrafficCongestionSummary(totalCongestionDist, totalCongestionTime, totalCongestionAvrSpeed), TrafficCongestionInfo(avrSpeed, roadName 등), TrafficEventInfo(eventType: ACCIDENT, ROAD_DAMAGE, REPAIRING, EVENT, DISASTER)
  • NavigationStatus: INACTIVE, INITIALIZING, FREE_DRIVE, ROUTE_DRIVE

NaviHelper에서 찾지 못한 것: 공개 API 목록에서 휴게소·졸음쉼터·주차장 같은 장소 유형 검색 API를 찾지 못했습니다. 경로 지점의 POI 유형은 NORMAL과 EV_CHARGING 두 가지뿐이고(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/navi-helper/ai.pleos.playground.navi.constants/route-point-poi-type/entry), requestRoute는 앱이 위도·경도·poiId를 직접 넘기는 방식입니다. 따라서 휴게소 안내를 하려면 앱이 휴게소 좌표를 별도 공개 데이터에서 가져와 경유지로 넣어야 합니다. 갱신 주기는 onCurrentRoadSpeedLimit의 1초만 명시되어 있고 나머지 이벤트 주기는 확인 못 함입니다.

2.5TextToSpeech SDK와 SpeechToText SDK

문서상 음성은 주행 중에도 허용되는 입력 방식입니다. 북미 정책은 주행 중 검색을 음성으로만 허용합니다(document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy). 주의 분산 설계 원칙은 음성 입력과 프리셋을 우선하라고 안내합니다(document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline). 다만 두 SDK 모두 공모전 상태가 준비 중이라는 점이 제약입니다.

2.6FusedLocation SDK

FusedLocation은 isSupported, initialize, getLastKnownLocation, registerFusedLocationCallback, unregisterFusedLocationCallback, showLocationAccessBlockedPopup, addProximityAlert, removeProximityAlert를 제공합니다. LocationData는 위도, 경도, 고도, 진행 방향, 신뢰도, 타임스탬프를 담습니다. 퍼미션은 pleos.car.permission.FUSED_LOCATION이며 차량 모델에 따라 지원 여부가 다릅니다(document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/intro, "제공 기능", "위치 데이터", "권한 및 접근 제약"). 공모전 상태는 준비 중입니다. 위치가 필요하면 사용 가능 상태인 NaviHelper의 getCurrentLocationInfo, onCurrentLocationInfo로 대체할 수 있습니다(2.4절).

2.7Gleo Interface와 AAOS 표준 Car API

Gleo Interface는 Gleo AI가 서드파티 앱을 음성 명령으로 호출하는 연동 규격이며, 별도 SDK는 아닙니다. 앱이 App Schema(JSON)에 function을 정의하면 LLM이 function call을 만듭니다. Gleo AI는 Gleo Action으로 앱을 호출하고 Callback으로 응답을 받습니다(document.pleos.ai/docs/pleos-only/app-integration-guide/guide/core-concepts). App Schema의 actionCalls는 최대 3개이고 호출 방식은 activity(startActivity) 또는 service(sendBroadcast)입니다(document.pleos.ai/docs/pleos-only/app-integration-guide/guide/app-capability, "2.1 Fields"). 즉 Gleo AI는 사용자가 말을 걸었을 때 앱을 부르는 구조이며, 앱이 Gleo AI에게 대화를 먼저 시작하게 하는 API는 문서에서 찾지 못했습니다. 공모전 FAQ와 개발 안내의 SDK 목록에는 Gleo Interface가 없습니다(appdevchallenge.auto-hmg.io/faq). App Schema 등록 절차와 공모전 사용 가능 여부는 확인 못 함입니다.

Pleos는 AAOS 표준 API에 같은 기능이 있으면 SDK에서 중복 제공하지 않고 표준 API 사용을 권장합니다. 문서는 속도, 기어 상태, 외기 온도, 연료 레벨을 AAOS Car API 대상 예시로 듭니다(document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/pleos-connect-sdk-api, "API 선택 기준"). 클러스터와 같은 속도는 CarPropertyManager로 PERF_VEHICLE_SPEED를 읽으라고 안내합니다(document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/vehicle-app-faq, "클러스터 속도 조회 방법").

표의 출처는 developer.android.com/reference/android/car/VehiclePropertyIds 의 각 상수 항목입니다. 표준 정의가 있어도 차량이 해당 프로퍼티를 실제로 제공하는지는 모델마다 다르며 CarPropertyManager로 확인해야 합니다(document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/api-compatibility-availability, "AAOS Vehicle Property 가용성"). Pleos Connect 실차가 PERF_VEHICLE_SPEED 외의 프로퍼티를 어디까지 제공하는지는 확인 못 함입니다. Virtual Console 셋업 가이드는 "차량 속도" 변경을 할 수 있다고 소개하지만 사용 가이드의 카드 목록에는 속도 카드가 없어, 에뮬레이터에서 속도를 바꾸는 방법은 확인 못 함입니다(document.pleos.ai/docs/connect/guide/getting-started/application-development/use-vehicle-emulator 및 document.pleos.ai/docs/pleos-only/app-test-guide/virtual-console-guide).

2.9주행 중 제한

  • 앱이 Distraction Optimization(DO)을 선언하지 않으면 주차 중에만 쓸 수 있고 주행 중에는 쓸 수 없습니다(document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy, "주행 상황에 따른 앱 사용 여부").
  • 주행 규제 상태에서 키보드, 다이얼패드, 설정, 동영상, 대용량 텍스트가 제한됩니다. 문서는 북미, 유럽, "그외 지역" 세 표만 제공하며 한국을 따로 명시하지 않습니다. 한국이 "그외 지역"에 속한다는 것은 추정입니다. "그외 지역"은 주행 중 키보드·다이얼패드·검색·미디어 앱 로그인과 내비게이션 검색을 허용하고, 차량 설정, 동영상, QR 로그인, 대용량 텍스트를 막습니다. 북미는 검색을 음성으로만 허용합니다(같은 페이지, "주행 상황별 기능 제한"). 지역 코드는 product.sw.target_region 값 KOR로 구분합니다(document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/vehicle-app-faq, "지역 코드 확인").
  • 앱은 AAOS CarUxRestrictionsManager의 onUxRestrictionsChanged로 제한 상태를 받아 반영해야 합니다(document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide). 에뮬레이터에서는 adb shell cmd hmg_car_service --service drivingstate driving 으로 주행 규제를 켤 수 있습니다(document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/adb-command-reference-guide, "주행 규제 활성화/해제").
  • 동영상, 게임, 브라우저 기능을 가진 미디어 앱은 운전 중 실행·사용할 수 없고, 운전이 시작되면 일시 중지하고 UI를 숨겨야 합니다(document.pleos.ai/docs/pleos-only/distribute/app-review-guide/review-driver-distraction-elements, "미디어 앱 설계").
  • 앱 카테고리 중 Music/Audio, Maps/Navigation, Mobility Services는 주행 중 일부 기능이 제한적으로 허용될 수 있고, Kids 카테고리도 따로 있습니다(document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-category).
  • 동승석 전용 화면이나 뒷좌석 화면을 위한 별도 규제나 API는 공개 문서에서 찾지 못했습니다(확인 못 함). Pleos Connect 플랫폼은 Connect-S, Connect-L, Connect-W 세 가지로 구분됩니다(document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/vehicle-app-faq, "실행 플랫폼 확인").

2.10Playground의 다른 공개 API(차량 앱 밖)

Pleos Playground에는 차량용 앱 SDK 외에도 API 문서가 공개되어 있습니다. 공모전 개발 안내는 이 API들을 공모전 SDK로 안내하지 않습니다(appdevchallenge.auto-hmg.io/guide/development).

Vehicle Data API의 목록에는 운전자 상태, 졸음, 실내 카메라 항목이 없습니다. 이 API는 차량 밖의 서버나 휴대폰 앱이 쓰는 경로이며, 국내 차종 지원 범위와 API 키 발급 조건은 로그인 필요로 확인 못 함입니다.

이 장은 SDK가 다루는 영역별로 운전자와 동승자가 실제로 겪는 문제, 그리고 기존 해결책이 부족한 이유를 정리합니다. 기관 발표를 인용한 기사는 재인용임을 밝혔습니다.

3.1운전 보조·안전: 졸음과 주의 분산

고속도로 졸음·주시태만

  • 2020~2024년 고속도로 전체 사고 8,280건 중 4,848건(58.6%)이 졸음·주시태만 사고였고, 설·추석 연휴에는 167건 중 109건(65.3%)이었습니다(한국도로공사 발표 인용, 뉴스핌 2025년 10월 2일, newspim.com/news/view/20251002001172).

졸음운전 사고 통계

  • 경찰청 집계로 2019~2023년 졸음운전 사고는 10,765건, 사망자는 316명이고 치사율(사고 100건당 사망자)은 2.9명으로 음주운전 1.5명의 약 2배였습니다. 고속도로 졸음운전 치사율은 8.3명입니다. 주간(06~18시) 사망자가 201명으로 야간 115명보다 많았습니다(정책브리핑 2024년 4월, www.korea.kr/news/policyNewsView.do?newsId=148927915).
  • 한국도로교통공단 발표에 따르면 2021~2023년 졸음운전 치사율은 2.7명으로 전체 교통사고 1.4명보다 높고, 사고는 12~18시에 몰리는 경향을 보였습니다(오토타임즈 2025년 4월, v.daum.net/v/2ozBNte7yM).

3.6뒷좌석 아이와 가족 이동

차내 방치

  • 2018년 7월 17일 동두천에서 4세 아동이 어린이집 차량에 7시간 10분 동안 갇혀 숨졌습니다(서울신문·연합뉴스 2018년 9월 7일, www.seoul.co.kr/news/society/2018/09/07/20180907800066).
  • 이 사고 뒤 어린이 통학버스 하차 확인장치가 2019년 4월 17일부터 의무가 되었습니다. 엔진 정지 후 3분 안에 차량 맨 뒤 버튼을 누르지 않으면 경고음과 비상점멸등이 작동합니다(www.ibabynews.com/news/articleView.html?idxno=73666 및 정부 브리핑 www.korea.kr/news/policyNewsView.do?newsId=148859879). 이 장치는 사람이 뒤까지 가게 만드는 절차이며 아이를 자동으로 감지하지 않습니다.
  • 미국 Kids and Car Safety 집계로 2024년 차내 고온 사망 아동은 41명이고, 1990~2024년 누적은 최소 1,126명입니다(www.kidsandcars.org/hot-cars/2024-deaths).
  • 같은 단체는 고온 차량 사망의 약 88%가 3세 이하라고 밝혔습니다(www.kidsandcars.org/news/hot-car-death-season-in-the-us-is-underway-what-can-be-done-to-save-children). NHTSA 원문은 접근이 차단되어 확인 못 함입니다. 국내 연도별 차내 방치 사망 통계도 확인 못 함입니다.
  • Euro NCAP은 2023년 평가부터 아동 존재 감지(CPD)에 점수를 주기 시작했습니다(www.euroncap.com/press-media/lexus-puts-safety-up-front-in-all-new-electric-rz/). 2025년 이후 세부 배점은 확인 못 함입니다.

현대·기아 후석 승객 알림의 작동 방식

  • 1차 알림은 뒷문을 열고 닫은 이력을 이용합니다. 시동을 끄고 운전석 문을 열면 뒷좌석 확인 메시지를 띄웁니다. 센서 사양은 1차 알림 뒤 문을 잠그면 약 10분 동안 실내 움직임을 감지하고, 감지하면 경적을 약 25초씩 최대 8회 울립니다(현대 2026년형 미국 설명서 ownersmanual.hyundai.com/full_webhelp/MX5aHEV/2026/en_US/id5afd08a9aae.html 및 기아 2023년형 한국어 설명서 ownersmanual.kia.com/full_webhelp/NQ5KH/2023/ko_KR/topics/t00421.html).
  • 기아 설명서는 1차 알림이 없으면 2차 알림도 작동하지 않는다고 적습니다. 작은 움직임, 담요나 보조 좌석의 가림, 센서 오염은 미감지 원인이고, 바람, 벌레, 진동은 오경보 원인입니다(같은 기아 설명서). 현대 STARIA의 일부 시장 사양은 레이더 센서를 씁니다(www.hyundai.com/worldwide/en/newsroom/detail/0000000538).

카시트와 안전띠

  • 2025년 유아용 카시트 착용률은 도시부도로 60.07%, 고속도로 66.25%였습니다. 고속도로 뒷좌석 안전띠 착용률은 69.65%였습니다(국토교통부·한국교통안전공단 교통문화실태조사 인용 보도 2026년 2월 1일, v.daum.net/v/20260201110121480). 다른 표본조사에서 2022년 뒷좌석 안전띠 착용률은 32.3%였습니다(www.fnnews.com/news/202309171101072946). 두 조사는 범위가 달라 직접 비교하지 않습니다.

부모 운전자의 주의 분산

  • 호주 Monash 대학 연구(2012년, 12가구 자연주행 영상)에서 운전자가 뒷좌석 아이와 상호작용한 빈도는 휴대전화 상호작용의 12배였습니다(research.monash.edu/en/publications/prevalence-of-mobile-phone-vs-child-related-driver-distraction-in/). 12배는 상호작용 빈도이며 충돌 위험을 뜻하지 않습니다. 관련 보도에 따르면 아이 관련 행동의 76.4%가 뒤돌아보거나 거울로 보는 행동이었고, 평균 16분 주행에서 3분 22초 동안 시선이 도로를 벗어났습니다(www.asianscientist.com/2013/10/in-the-lab/children-distracting-mobile-phones-2013/).
  • 애프터마켓 아이 확인용 거울이 충돌 때 떨어지거나 깨져 다칠 수 있다는 카시트 안전 안내가 있습니다(www.vumc.org/injuryprevention/node/228). 이 주소가 보여 주는 본문의 작성 기관은 확인 못 함입니다. 뒷좌석 카메라 제품은 2015년에도 있었지만(Garmin babyCam, www.garmin.com/en-US/newsroom/press-release/automotive/2015-adding-multimedia-garmin-delivers-babycam-the-worlds-first-video-monitor-navigation-system/), 화면을 보는 시간이 남는다는 점은 이 보고서의 해석이며 측정된 값은 없습니다.

멀미와 지루함

  • CDC는 멀미가 2~12세 아동에게 더 흔하고, 지평선 보기, 눈 감기, 음악 듣기를 비약물 대처법으로 제시합니다(wwwnc.cdc.gov/travel/page/motion-sickness). 한국 아동 유병률은 확인 못 함입니다.
  • 영국 부모 2,000명 조사(2022년)에서 68%가 뒷좌석 짜증의 원인으로 지루함을 꼽았고, "거의 다 왔어요?"는 출발 32분 뒤에 나왔습니다(www.rte.ie/news/newslens/2022/0822/1317041-are-we-there-yet-formula-created-to-predict-tantrums/). 상업 후원 조사입니다.
  • 2025년 추석 특별교통대책기간 예상 이동인원은 3,218만 명이고 승용차 비중은 84.5%였습니다(국토교통부 대책 게시, www.kric.go.kr/jsp/board/portal/sub01/railNewsDetail.jsp?p_id1=M01060101&p_id2=661585&p_id3=2025.09.29). 전국 평균 귀성 소요시간은 확인 못 함입니다.

기존 해결책의 한계: 하차 확인장치는 버튼 절차이고, 후석 승객 알림은 문 개폐 이력과 10분 감지라는 조건이 붙어 있습니다. 거울과 카메라는 운전자의 시선을 다시 화면으로 끌어옵니다. 차량 앱은 좌석별 점유(getCurrentSeatOccupancy), 안전벨트(getCurrentSeatBeltBuckledState), 도어(getCurrentDoorPosition), 도어 잠금, 실내 온도(getHvacTemperatureCurrent)를 normal 권한으로 읽을 수 있습니다(2.3절). 다만 차량 앱은 시동이 꺼진 뒤 계속 동작한다는 근거가 문서에 없어, 하차 후 방치 감지는 앱 단독으로 보장할 수 없습니다(확인 못 함).

3.7동승자 엔터테인먼트

  • BMW 7시리즈(2022년)는 31인치 뒷좌석 화면을 제공합니다(www.press.bmwgroup.com/usa/article/detail/T0382613EN_US/the-new-bmw-7-series). BMW 5시리즈의 AirConsole 게임은 스마트폰을 컨트롤러로 쓰며 정차 중에 함께 즐기는 방식입니다(2023년, www.press.bmwgroup.com/usa/article/detail/T0419599EN_US).
  • Audi는 동승석 화면이 있는 차량에서 운전자에게 화면이 보이지 않게 하는 프라이버시 모드로 주행 중 게임을 제공합니다(2025년, www.audi-mediacenter.com/en/press-releases/gaming-fun-on-the-go-audi-integrates-airconsole-16729). Mercedes-Benz E-Class는 운전자 눈의 움직임을 카메라로 보고 동승석 화면 밝기를 낮춥니다(media.mbusa.com/news/the-new-e-class-dimensional-concept-and-interior-design).
  • Tesla는 2021년 12월 중앙 화면의 주행 중 Passenger Play를 OTA로 비활성화했고, NHTSA는 조사를 종결했습니다(AP 보도 2023년 5월 30일, www.cbsnews.com/detroit/news/us-ends-probe-into-tesla-allowing-video-games-while-vehicles-are-moving-says-feature-was-disabled/).
  • 국내에서는 현대 블루링크 스트리밍 요금제에 게임이 있고 ccNC 차량에 한정됩니다(www.hyundai.com/kr/ko/digital-customer-support/app/myhyundai/bluelink-registration). 기아 커넥트 스토어는 차량용 아케이드 게임 8종을 안내합니다(connectstore.kia.com/kr/info/product-usage-guide-incargame).
  • 미국 성인 조사(2024년 발표)에서 뒷좌석 화면을 원한다는 응답은 58%였습니다. 이 값은 선호이며 실제 이용률이 아닙니다(wctvtv.marketminute.com/article/bizwire-2024-6-12-dts-reports-radio-remains-crucial-while-video-and-gaming-surge-in-vehicle). 한국 승객의 이용률은 확인 못 함입니다.
  • 도로교통법 제49조 제1항 제11호는 운전 중 "운전자가 운전 중 볼 수 있는 위치에 영상이 표시되지 아니하도록" 하라고 정하고, 정지 중이거나 지리안내·교통정보·긴급상황·주변 확인 영상인 경우를 예외로 둡니다. 제11호의2는 운전 중 영상표시장치 조작을 금지합니다(www.law.go.kr/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=1000842761). 2026년 현행 조문과의 일치는 확인 못 함입니다.

기존 해결책의 한계: 해외 차량 게임은 정차 중 전용이거나 별도 동승석 화면과 시선 차단 장치를 전제합니다. Pleos 문서는 동영상, 게임, 브라우저 앱을 주행 중 실행할 수 없게 하라고 요구하고(2.9절), 동승석 전용 화면 API는 공개 문서에서 찾지 못했습니다. 따라서 주행 중 동승자 참여는 화면을 쓰지 않는 음성·오디오 방식이나 승객의 휴대폰을 쓰는 방식만 남습니다.

판정 기준은 1장과 같습니다. "가능"은 지금 쓸 수 있는 공개 API로 필요한 데이터를 모두 얻는 경우, "부분"은 일부만 얻거나 준비 중 SDK·외부 데이터에 기대는 경우, "불가"는 핵심 데이터가 signature|privileged 권한 뒤에 있거나 공개 API가 없는 경우입니다. 이 표는 순위가 아니며 아이디어를 고르지 않습니다. API 출처는 2장의 해당 절에 있습니다.

교차표에서 반복되는 사실은 세 가지입니다. 첫째, 운전자 상태와 ADAS 경고는 공개 API로 받을 수 없습니다. 둘째, 좌석 점유·안전벨트·도어·배터리·주행 시간 같은 차량 상태와 내장 내비게이션 데이터는 지금 쓸 수 있습니다. 셋째, 음성 입출력과 차량 제어는 준비 중이어서 공모전 일정 안에 쓸 수 있는지가 불확실합니다.

이 장은 세 후보를 같은 기준으로 판정합니다. 어느 후보를 고를지는 판단하지 않습니다.

5.1졸음운전 대응(ADAS 감지 + Gleo AI 대화 + NaviHelper 휴게소 안내)

판정: 부분. 후보가 내건 "ADAS로 졸음 감지"는 불가입니다. "공개 ADAS·차량 데이터로 졸음·부주의를 실제로 알 수 있는가"에 대한 답은 "알 수 없다"입니다. 부분 판정은 공개 데이터로 구현할 수 있는 나머지 기능, 즉 주행 시간과 시각에 근거한 피로 위험 추정과 휴게소 경유지 안내를 가리킵니다. 차량에는 이미 운전자 주의 경고(DAW)가 있고, 휴식 알림이 실제 휴식으로 이어지지 않았다는 연구가 있습니다(3.1절).

5.2뒷좌석 아이 케어

판정: 부분. 읽기 기능은 가능하고 제어·영상·하차 후 감지는 부분 또는 불가입니다. 주행 중 뒷좌석 착좌·안전벨트·도어·실내 온도를 모니터링하는 기능은 지금 공개 API로 만들 수 있고 에뮬레이터로 시연할 수 있습니다. 아이의 상태를 보거나 듣는 기능과 하차 후 방치 감지는 공개 API로 보장할 수 없습니다. 기존 후석 승객 알림과 하차 확인장치는 하차 시점을 다룹니다(3.6절). 차량이 주행 중 뒷좌석 안전벨트 경고를 이미 어디까지 제공하는지는 차종별로 다르며 이 조사에서 확인 못 했습니다.

5.3동승자 참여형 엔터테인먼트

판정: 부분. 주행 중 화면을 쓰는 엔터테인먼트는 정책과 법령으로 막혀 있습니다. 주행 중에는 위치·경로와 좌석 점유를 쓰는 오디오·음성 중심 참여만 가능하고, 음성 SDK가 준비 중이라는 점이 공모전 일정상 위험입니다. 정차·충전 중 화면 콘텐츠는 가능합니다.

5.4세 후보 공통 위험

  • 준비 중 SDK 의존: TextToSpeech, SpeechToText, FusedLocation, Vehicle Control은 공모전 접수 기간(2026년 10월 21일~11월 15일)과 2차 PT(12월 3~4일) 전에 "사용 가능"으로 바뀐다는 공지를 찾지 못했습니다(일정 appdevchallenge.auto-hmg.io/, 공지 목록 appdevchallenge.auto-hmg.io/notice).
  • 심사와 출시는 다릅니다. 공모전은 에뮬레이터 시연을 인정하지만, App Market 출시에는 퍼미션 사전 승인과 주의 분산 심사가 따로 있습니다(2.1절).
  • 차종별 지원: 모든 Vehicle SDK 기능은 checkXXXCapabilities로 지원 여부를 확인하도록 설계해야 합니다(2.2절).
