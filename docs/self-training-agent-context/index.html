  • NVIDIA 연구(2026년 11월)는 하네스의 자동 요약 대신 모델이 직접 줄일 범위를 고르고, 원래 기록은 보관해 다시 꺼내게 했습니다. 32K 예산에서 GPT-6.1 Sol의 점수가 21%에서 56%로 올랐습니다. 그러나 같은 도구를 Claude Opus 5.5는 과제의 4%에서만 썼습니다. 경고를 받은 Opus는 88%의 경우 바로 답을 냈습니다(5절).
  • 받은 의료 LLM 문헌 4편의 요약 수치는 원문과 맞습니다. Ferber 논문의 91.0%는 평가 문장 245개 중 223개가 맞았다는 뜻이고, 사례 비율이 아닙니다. Soroush 논문(NEJM AI)은 학술지 본문을 열지 못해 최종판 초록으로만 확인했습니다(6절).
  • closed model의 추론 과정이 숨겨져 있어도 도구 호출과 관찰 결과만으로 소형 모델에 정책을 옮길 수 있습니다. CoT-Proxy 연구에서 행동만 학습한 Qwen3-4B는 AppWorld 성공률이 7.3%에서 17.9%로 올랐고, 추론 요약을 별도 위치에 더하면 34.5%였습니다. 다만 OpenAI, Anthropic, Google 약관은 출력으로 경쟁 모델을 만드는 일을 금지합니다(8절).
  • 텍스트-SQL·EHR 질의 에이전트에는 다섯 가지를 권합니다. 잘린 결과에 잘림 표시와 다시 꺼내는 도구를 붙입니다. 빈 결과와 "기록 없음"을 구분합니다. 코드는 사전과 뷰에서 찾게 합니다. 정답률 밖에 답 못 함 판단과 calibration을 잽니다. self-training은 평가 문항과 분리한 합성 질문과 실행 결과 일치 필터로 합니다(7절).

2.1대회 과제와 평가 지표

EHRSQL 2024는 NAACL 2024 ClinicalNLP 워크숍의 공유 과제입니다. 참가자는 자연어 질문을 MIMIC-IV demo DB의 SQL로 바꿉니다. demo DB에는 환자 100명의 기록이 있고, 스키마는 전체 MIMIC-IV와 같습니다. DB로 답할 수 없는 질문에는 SQL 대신 null을 냅니다. 100명 이상이 신청했고, 8개 팀이 코드와 fact sheet까지 제출했습니다. [출처: arxiv.org/pdf/2405.06673, 3.2절, 5.1절]

질문 템플릿은 국내 한 대학병원 의료진 200명 이상에게 받은 질문에서 나왔습니다. 원래 EHRSQL의 답 못 하는 질문은 쉽게 걸러졌기 때문에, 대회는 TrustSQL의 적대적인 답 못 하는 질문을 더했습니다. 이 새 질문은 검증과 시험 세트에만 넣었습니다. [출처: arxiv.org/pdf/2405.06673, 3.1절, 3.4절]

값은 대회 개요 논문 Table 1에서 가져왔고, 마지막 줄은 그 값으로 계산했습니다. [출처: arxiv.org/pdf/2405.06673, Table 1]

개요 논문 3.5절은 "각 분할에 답할 수 없는 질문이 20%"라고 씁니다. 그러나 같은 논문 Table 1에서 학습 세트의 비율은 8.8%입니다. 이 보고서는 Table 1의 값을 따릅니다.

주 지표는 Reliability Score RS(c)입니다. 문항마다 아래 점수를 매기고 평균합니다. [출처: arxiv.org/pdf/2405.06673, 4.1절 식 (1)] [출처: arxiv.org/pdf/2405.11162, Figure 2]

c는 0, 5, 10, N(문항 수)입니다. 순위는 RS(10)으로 정합니다. RS(10)에서는 틀린 답 하나가 맞는 답 10개를 지웁니다. 모든 질문에 답하지 않으면 답 못 하는 질문 비율만큼인 20점을 받습니다. 대회는 이 ABSTAIN-ALL을 기준선으로 씁니다. 가능한 최저점은 RS(10)에서 -1000점, RS(N)에서 -100N점입니다. [출처: arxiv.org/pdf/2405.06673, 4.1절, 4.3절, Table 3]

2.2방법

논문 제목은 "LG AI Research & KAIST at EHRSQL 2024: Self-Training Large Language Models with Pseudo-Labeled Unanswerable Questions for a Reliable Text-to-SQL System on EHRs"입니다. 저자는 Yongrae Jo, Seongyun Lee, Minju Seo, Sung Ju Hwang, Moontae Lee입니다. ClinicalNLP 2024 논문집 635~643쪽에 실렸습니다. [출처: aclanthology.org/2024.clinicalnlp-1.61/]

방법은 두 단계 self-training과 두 단계 필터입니다. [출처: arxiv.org/pdf/2405.11162, 3절, Figure 1]

  1. 시드 모델 학습: GPT-3.5-Turbo-0125를 OpenAI 파인튜닝 API로 학습 세트 전체에 학습합니다. 입력에는 글로 바꾼 DB 스키마와 답 못 하는 질문의 기준을 넣습니다(Figure 3).
  2. 의사 라벨: 시드 모델이 라벨 없는 검증·시험 질문마다 SQL 또는 null을 예측합니다. null로 예측한 질문 K개만 null 라벨로 학습 세트에 더합니다. 정답 SQL을 모르는 답할 수 있는 질문은 더하지 않습니다.
  3. 재학습: 늘린 학습 세트로 모델을 다시 학습합니다. 반복은 한 번입니다.
  4. 최대 token entropy 필터: 예측 안에서 entropy가 가장 큰 token의 값을 예측의 entropy로 정합니다. entropy 상위 7%를 null로 바꿉니다. 이 비율은 예측할 세트의 답 못 하는 질문 비율에 맞춘 hyperparameter입니다(Table 4 설명).
  5. 실행 필터: 남은 SQL을 sqlite3로 실행합니다. 오류가 나거나, 결과가 비었거나, None이면 null로 바꿉니다.

저자들은 self-training의 이유를 두 가지로 듭니다. 첫째, 학습 세트에 답 못 하는 질문이 적어 class 불균형이 있습니다. 둘째, OpenAI text-embedding-3-large로 잰 학습 질문과 검증·시험 질문의 embedding cosine 유사도 평균이 0.36과 0.34로 낮습니다. [출처: arxiv.org/pdf/2405.11162, 3.2절]

  • self-training 단계만 뺀 ablation은 논문에 없습니다. Table 2는 모델, Table 3은 입력, Table 4는 필터의 효과만 보여 줍니다. 그래서 RS 향상 중 의사 라벨 재학습의 몫은 확인할 수 없습니다. 더한 null 질문의 수 K는 Figure 1과 그 설명에 기호로만 나오고 값이 없습니다. arXiv판과 ACL Anthology판 모두 같으며, 두 판에 appendix가 없습니다. [출처: arxiv.org/pdf/2405.11162, Figure 1, Table 2~4] [출처: aclanthology.org/2024.clinicalnlp-1.61.pdf, Figure 1]
  • 의사 라벨은 라벨 없는 검증·시험 질문 자체에 붙입니다. 정답은 쓰지 않지만 시험 입력 분포를 학습에 씁니다(transductive). 저자들은 실제 서비스에서는 사용자 질문을 쉽게 모을 수 있다는 점을 이유로 듭니다. [출처: arxiv.org/pdf/2405.11162, 1절, 3.2절] 대회 주최 측은 시험 시점 의사 라벨 파인튜닝이 고정된 벤치마크에서는 효과적이지만 실시간 배포에 바로 적용하기는 어려울 수 있다고 평가했습니다. [출처: arxiv.org/pdf/2405.06673, 5.2절 관찰 5]
  • 실행 필터는 결과가 빈 SQL을 답 못 함으로 바꿉니다. 실제 EHR에는 "해당 기록 없음"이 맞는 답인 질문이 있습니다. 이런 질문에서는 빈 결과가 정답입니다(7.2절). OmniSQL도 EHRSQL로 평가할 때 답 못 하는 질문과 결과가 빈 질문을 빼고 평가했습니다(3.4절).
  • PLUQ 논문 안에서 학습 세트 크기의 표기가 다릅니다. 3.1절과 4.1절은 두 종류 질문을 합쳐 5,124개라고 쓰고, 3.2절은 답할 수 있는 질문이 5,124개이고 답 못 하는 질문이 450개라고 씁니다. 개요 논문 Table 1에 따르면 답할 수 있는 질문 4,674개와 답 못 하는 질문 450개를 합쳐 5,124개입니다. 3.2절의 5,124는 합계를 잘못 옮긴 값입니다. STaR(Zelikman et al., 2022). - 몇 개의 예시로 rationale과 답을 만들고, 답이 맞은 rationale만 모아 학습합니다. 틀린 문제는 정답을 힌트로 주고 rationale을 다시 만듭니다(rationalization). - 새 데이터를 모을 때마다 처음 사전학습 모델에서 다시 학습합니다. 저자들은 과적합을 피하려는 선택이라고 씁니다. [출처: arxiv.org/pdf/2203.14465, 3.1절]

[출처: arxiv.org/pdf/2203.14465, Table 1]

  • 한계: 첫 반복이 되려면 few-shot 성능이 우연보다 높아야 합니다. GPT-2는 산술에서도 시작하지 못했습니다. 이진 선택처럼 우연히 맞힐 확률이 높은 과제에서는 나쁜 rationale이 많이 섞입니다. rationale 자체의 정확성은 따로 확인하지 않습니다. [출처: arxiv.org/pdf/2203.14465, 6절 한계 단락]

ReST(Gulcehre et al., 2023). - Grow 단계에서 정책 모델로 샘플을 만들고, Improve 단계에서 보상으로 거른 데이터에 offline RL을 합니다. Grow 단계의 데이터를 여러 Improve 단계에서 다시 쓰므로 online RLHF보다 계산이 적다고 씁니다. [출처: arxiv.org/pdf/2308.08998, 1절, 2절] - 기계 번역(IWSLT 2014, WMT 2020, 내부 Web Domain)에서 보상 모델 점수와 사람 평가가 모두 지도 학습 기준보다 좋았습니다. 보고서에 옮긴 수치는 없습니다. [출처: arxiv.org/pdf/2308.08998, 4절]

ReST-EM(Singh et al., 2023, Beyond Human Data). - 샘플 생성, 이진 정답 신호로 거르기, 학습을 몇 번 되풀이합니다. 매 반복 처음 사전학습 모델을 학습해 과제 과적합을 줄입니다. [출처: arxiv.org/pdf/2312.06585, 3절] - PaLM 2로 MATH(학습 문제 7,500개)와 APPS Introductory(2,342개)에서 사람 데이터로 파인튜닝한 것보다 좋았고, 큰 모델(PaLM 2-L)에서 차이가 컸습니다. 결과는 그림으로만 나옵니다. [출처: arxiv.org/pdf/2312.06585, 4절, Figure 2, Figure 3] - 이전 반복 모델에서 이어 학습하는 ReST와 비교하면, APPS 점수는 비슷하지만 HumanEval 전이는 ReST-EM이 훨씬 좋았습니다. 처음 모델에서 다시 학습하는 선택의 근거입니다. [출처: arxiv.org/pdf/2312.06585, Figure 7] - 사람이 쓴 풀이 7천 개로 한 SFT보다 생성 풀이 5천 개로 한 ReST-EM이 MATH에서 높았습니다. [출처: arxiv.org/pdf/2312.06585, Figure 6] - 한계: 반복을 몇 번 넘기면 향상이 줄어듭니다. 학습 세트 점수와 시험 세트 점수의 차이가 반복마다 벌어지며, 저자들은 적은 학습 문제에 대한 과적합을 원인으로 듭니다. 새 과제마다 문제 세트와 자동 보상 함수가 필요합니다. [출처: arxiv.org/pdf/2312.06585, Figure 4, 6절] - Big-Bench Hard에서는 큰 성능 저하가 없었습니다. [출처: arxiv.org/pdf/2312.06585, Figure 9]

  • 의료 질의에서 드문 질문 유형, 드문 코드, 드문 기록 형태가 이 꼬리에 해당합니다. self-training 데이터에는 실제 질문과 실제 DB 실행 결과를 계속 섞어야 합니다.

4.1무엇을 학습시키나

논문은 Gandhi et al., "Stream of Search (SoS): Learning to Search in Language"(2024)입니다. 언어 모델은 학습 때 쓸모 있는 실수를 거의 보지 못하고, 그래서 오류가 눈덩이처럼 커진다는 문제에서 시작합니다. 저자들은 탐색 과정 전체를 한 줄의 글로 펼쳐 학습시킵니다. [출처: arxiv.org/pdf/2404.03683, 1절]

  • 과제: Countdown입니다. 입력 숫자들을 사칙연산으로 묶어 목표 숫자를 만듭니다. 24 게임을 넓힌 문제입니다. 목표 숫자의 10%는 분포 밖 평가용으로 남겼습니다. [출처: arxiv.org/pdf/2404.03683, 3절]
  • 직렬화: 탐색, 되돌아가기(backtracking), 목표 확인을 글로 명시합니다. heuristic 값, 상태 값, 가지치기 전략은 글에 쓰지 않습니다. [출처: arxiv.org/pdf/2404.03683, 2절, Figure 2]
  • 데이터: BFS와 DFS를 바탕으로, 간단한 heuristic 함수 2개를 쓰는 탐색 전략 12개로 궤적을 만듭니다. 문제는 50만 개입니다. SoS 데이터에서 정답에 이른 궤적은 285,501개(57.1%)이고, 최적 경로(OP) 데이터는 50만 개 모두 정답입니다. [출처: arxiv.org/pdf/2404.03683, 4절, Appendix B]
  • 모델: GPT-Neo 250M(16층, hidden 1,024), 문맥 4,096 token, 처음부터 사전학습합니다. 두 조건은 같은 gradient step 수만큼 학습합니다. [출처: arxiv.org/pdf/2404.03683, 4절, Appendix C.1]

4.2결과

OP와 SoS의 비교는 본문 4절과 Figure 3(a), 나머지는 Appendix의 Table 1과 Table 2에서 가져왔습니다. [출처: arxiv.org/pdf/2404.03683, 4절, Figure 3(a), Table 1, Table 2]

  • 정답 궤적 수가 더 적은 SoS 데이터가 더 좋은 모델을 만듭니다. 실수와 되돌아가기를 보여 준 것이 효과를 냅니다. 다만 SoS 모델의 정확도는 데이터를 만든 탐색 전략들의 평균보다 조금 낮습니다. [출처: arxiv.org/pdf/2404.03683, 4절, Figure 3(a)]
  • STaR는 반복마다 정답 궤적 10만 개를 만들고, 3번 반복 후 수렴했습니다. 매 반복 기본 SoS 모델에서 다시 학습합니다. APA는 reference policy를 3번 재설정한 뒤 향상이 멈췄습니다. 본문은 향상 폭을 STaR 약 5%, APA 약 6%로 적습니다. [출처: arxiv.org/pdf/2404.03683, 5절, Figure 4, Appendix C.4]
  • 정책 개선 뒤에는 궤적당 산술 오류가 줄고, 맞은 풀이에서 방문한 상태 수도 줄었습니다. 다만 STaR 모델은 탐색 오류(0.008에서 0.024)와 기타 오류(0.018에서 0.069)가 늘었습니다. [출처: arxiv.org/pdf/2404.03683, Figure 6, Table 2]

4.3관련 연구

  • Searchformer(Lehnert et al., 2024)는 A* 탐색의 진행(상태를 탐색 트리에 넣고 빼는 순서)을 token 열로 학습시킨 뒤, 더 짧은 탐색 열을 내도록 파인튜닝합니다. 보지 못한 Sokoban 문제의 93.7%를 최적으로 풉니다. 탐색 단계 감소 폭 26.8%는 초록에서는 "최대", 본문 1절에서는 "평균"으로 적혀 있어 논문 안에서 표현이 다릅니다. [출처: arxiv.org/pdf/2402.14083, 초록, 1절]

4.4텍스트-SQL 에이전트 궤적과의 대응

SoS의 결과에 따르면, 탐색과 복구가 담긴 궤적 전체를 학습한 모델이 최종 SQL만 학습한 모델보다 나을 것으로 예상합니다. 다만 SoS 궤적은 4,096 token 안에 들어가고, 에이전트 궤적은 도구 결과 때문에 훨씬 깁니다. 궤적을 학습 데이터로 쓰려면 긴 도구 결과를 줄이는 규칙(5절)이 함께 필요합니다. 또 STaR로 정답 궤적만 다시 학습하면 탐색 오류가 늘 수 있으므로(4.2절), 궤적 단위의 오류 종류도 함께 잽니다.

7.1도구 결과가 잘리는 문제

EHR 질의 에이전트는 긴 결과를 자주 받습니다. 행이 많은 검사 결과, 긴 서술형 기록이 그 예입니다. 하네스가 결과를 일정 행이나 글자 수로 자르면, 모델은 뒷부분에 있던 기록을 못 보고 "기록 없음"이라고 답할 수 있습니다. 5절의 연구는 하네스가 대신 줄이면 필요한 정보가 빠질 수 있다는 같은 문제를 다룹니다.

권하는 설계는 다음과 같습니다. 1. 잘린 결과에는 잘렸다는 표시, 전체 행 수, 전체 길이를 함께 보여 줍니다. 2. 원래 결과는 지우지 않고 보관합니다. 결과마다 id를 붙이고, 모델이 id와 범위(행 번호, 글자 위치)로 잘린 부분을 다시 꺼내는 도구를 줍니다. NVIDIA 연구의 보관과 tag 조회와 같은 구조입니다. 3. SQL 에이전트에서는 다시 꺼내기 대신 같은 질의에 LIMIT, OFFSET, WHERE 조건을 붙여 다시 실행하게 할 수도 있습니다. 4. 잘린 결과만 보고 "없음"이라는 부정 결론을 내지 말라는 규칙을 시스템 지시에 넣습니다. 5. 도구 사용률을 잽니다. NVIDIA 연구에서 같은 도구를 Opus 5.5는 4%만 썼고, 경고를 받으면 88%의 경우 바로 답을 냈습니다. 모델이 도구를 잘 쓰지 않으면, 잘림 표시를 더 눈에 띄게 하거나 부정 결론 전에 하네스가 확인을 요구합니다. 6. 평가 지표에 잘린 결과 뒤의 부정 답 비율과 다시 꺼낸 비율을 넣습니다.

7.2답 못 함 판단과 "기록 없음"

  • EHRSQL 2024의 RS처럼 틀린 답에 벌점을 주는 지표로 평가하면, 답 못 함 판단의 가치가 점수에 드러납니다. 모두 답하지 않는 기준선(20점)도 함께 보고합니다(2.1절).
  • 상위 팀은 모두 불확실성 신호(token entropy, log-probability, 여러 샘플이나 여러 모델의 합의)로 답을 걸렀습니다. token 확률을 주지 않는 API 모델에서는 여러 번 샘플링한 SQL 결과의 합의가 쓸 수 있는 신호입니다(2.4절).
  • "DB로 답할 수 없는 질문"과 "답할 수 있고 정답이 빈 결과인 질문"을 구분합니다. PLUQ의 실행 필터는 빈 결과를 답 못 함으로 바꾸고, OmniSQL은 이런 질문을 평가에서 뺐습니다. 실제 EHR에서 "해당 환자에게 그 검사 기록이 없음"은 맞는 답일 수 있습니다. 평가 세트에도 두 종류를 따로 넣습니다.

7.3코드와 용어는 사전과 뷰에서 찾게 하기

GPT-4도 코드 설명에서 ICD-9-CM, ICD-10-CM, CPT 코드를 정확히 만든 비율이 50% 미만입니다(6절). 에이전트가 코드를 기억으로 만들지 않고, 코드 사전 테이블이나 뷰를 조회해 찾게 합니다. 사전 조회 결과가 없으면 코드를 지어내지 말고 그 사실을 답에 적게 합니다.

7.4평가 설계

  • 실제 환자 데이터(또는 실제 EHR 구조의 DB)로 평가합니다. Bedi et al.이 본 519편 중 5%만 실제 진료 데이터를 썼습니다.
  • 정답률 밖의 차원을 잽니다. calibration·uncertainty를 잰 연구는 1.2%뿐입니다. 답 못 함 판단, 확신도와 정답의 관계, 도구 사용 정확도를 함께 잽니다.
  • Ferber et al.처럼 도구 호출의 정확도(필요한 도구를 맞게 불렀는지, 빠뜨린 도구와 필요 없는 호출)와 최종 결론의 정확도, 해로울 수 있는 답의 비율을 따로 잽니다.
  • 평균 점수만 보지 않습니다. OmniSQL은 9개 데이터셋 평균에서 GPT-4o보다 높지만 EHRSQL에서는 낮습니다(3.4절). 의료 DB 점수는 따로 보고합니다.

7.5self-training을 적용한다면

  1. 학습 질문: 평가 문항으로 학습하지 않습니다. 평가와 분리한 합성 질문을 템플릿이나 강한 모델로 만듭니다(KU-DMIS, OmniSQL). 실제 운영 질문을 쓸 때는 평가 세트와 겹치지 않게 분리합니다. PLUQ처럼 시험 입력에 의사 라벨을 붙이는 방식은 고정 벤치마크에서만 쓸 수 있다는 주최 측 평가가 있습니다(2.5절).
  2. 궤적 생성: 에이전트가 각 질문을 여러 번 풉니다. 스키마 탐색, SQL 오류, 수정이 담긴 궤적 전체를 남깁니다(SoS).
  3. 거르기: 최종 SQL의 실행 결과가 정답 SQL의 실행 결과와 같은 궤적만 남깁니다(STaR, RFT, ReST-EM). 답 못 하는 질문은 null 라벨로 따로 늘려 class 불균형을 줄입니다(PLUQ). 쉬운 질문의 궤적이 몰리지 않게 질문당 궤적 수에 상한을 둡니다(SWE-smith).
  4. 오답 궤적: 버리지 않고 verifier나 선호 학습에 씁니다(V-STaR, SENSE). 다만 SENSE에서 오답 데이터의 몫은 BIRD dev 2.6점으로, 강한 정답 데이터의 몫보다 훨씬 작습니다.
  5. 학습: LoRA나 QLoRA 같은 parameter-efficient 파인튜닝으로 합니다. 반복은 2~3회로 두고, 매 반복 처음 모델에서 다시 학습합니다(STaR, ReST-EM Figure 7). SPIN에서 반복 3의 향상은 +0.19뿐이었습니다. 생성 데이터만 되풀이하지 않고 실제 질문과 실제 실행 결과를 섞습니다(model collapse).
  6. 문맥 관리 행동: 긴 결과를 줄이고 다시 꺼낸 궤적 중 정답에 이른 것을 학습 데이터에 넣으면, 5절에서 저자들이 말한 문맥 관리 학습이 됩니다.

8.1질문

closed model은 추론 과정을 숨기거나 요약해서 보여 줍니다. 그러나 에이전트 작업에서는 도구 호출, 인자, 도구가 돌려준 관찰 결과가 로그로 남습니다. 하네스를 씌운 teacher의 궤적을 SFT 데이터로 쓰는 방식도 흔합니다. 이 절은 세 가지를 봅니다.

  1. 추론 없이 도구 호출 순서와 결과만 있는 궤적으로 SFT하면 무엇이 빠지는지 봅니다.
  2. 빠진 부분을 메우는 방법과 그 효과 수치를 봅니다.
  3. 약관상 제약과 대안을 봅니다.

8.3추론 없이 행동만 있는 궤적에서 빠지는 것

궤적에서 생각을 빼고 행동만 남기면 다음이 빠집니다.

  • 행동을 고른 이유: ReAct 논문에서 HotpotQA 정답 궤적 3,000개로 PaLM-8B·62B를 파인튜닝하면, 생각과 행동을 함께 학습한 ReAct가 행동만 학습한 Act보다 높았습니다. 다만 Act도 답만 학습한 Standard나 CoT보다는 훨씬 높았습니다. 결과는 그림으로만 나옵니다. [출처: arxiv.org/pdf/2210.03629, 3.3절, Figure 3]
  • 형식 밖의 내용: Agent-FLAN은 ReAct·JSON 형식의 학습 데이터에서 형식 부분의 loss가 빨리 0 가까이 떨어지고(0.04), 내용 부분의 loss는 높게 남는다(0.54)고 보고합니다. 고정된 형식을 먼저 외우고 추론은 덜 배운다는 뜻입니다. 형식을 일반 대화 형식으로 바꾸면 T-Eval이 61.8에서 64.9로, HotpotQA가 25.4에서 27.9로 오릅니다. [출처: arxiv.org/pdf/2403.12881, 3절, Table 2]
  • 문체만 옮겨지는 위험: ChatGPT 출력으로 모방 학습한 모델은 사람 평가자에게 좋은 점수를 받지만, 모방 데이터가 다루지 않은 과제(Natural Questions)에서는 기반 모델보다 거의 나아지지 않습니다. 저자들은 모방 모델이 ChatGPT의 문체는 따라 하지만 사실성은 따라 하지 못한다고 정리합니다. [출처: arxiv.org/pdf/2305.15717, 1절, Figure 1, 4절]
  • 평가 방식에 따라 차이가 숨습니다. Orca 논문은 GPT-4 판정으로는 Vicuna가 ChatGPT 품질의 92%를 유지하지만, 사람 라벨 기준으로는 AGIEval에서 64%, BigBench-Hard에서 48%만 유지한다고 보고합니다. [출처: arxiv.org/pdf/2306.02707, 1절]
  • 실패에서 배울 정보: 정답 궤적만 학습하면 teacher가 피한 실수를 볼 수 없습니다. 실패 궤적을 쓰면 오릅니다. NAT는 실패 궤적에 실패 표시를 붙여 함께 학습해 HotpotQA 7B 점수를 정답만 쓴 55.40에서 65.80으로 올렸고, 표시 없이 섞으면 62.40이었습니다. ETO는 실패-성공 궤적 쌍으로 대조 학습해 SFT보다 WebShop 평균 보상을 8%, ScienceWorld를 9.5% 올렸습니다. [출처: arxiv.org/pdf/2402.11651, Table 3, Table 6] [출처: arxiv.org/pdf/2403.02502, 4.2절, Table 2]

CoT-Proxy(Kopiczko et al., 2026)는 이 질문을 직접 시험했습니다. teacher 궤적에서 추론을 빼고 행동만 남긴 뒤, student의 추론 칸을 비워 둔 채 학습합니다. 자기 생성 데이터에 대한 KL loss로 처음 모델에서 멀어지지 않게 합니다. [출처: arxiv.org/pdf/2611.33148, 2절, 식 (1)]

  • 같은 궤적에서 distillation과 self-training을 비교한 결과도 있습니다. ETO와 ActRe는 teacher 궤적으로 SFT한 뒤 student가 스스로 탐색한 궤적으로 더 학습해 SFT보다 높아졌습니다(8.3절, 위 표). ETO에서 teacher 궤적 없이 처음부터 자기 탐색만 한 경우는 Table 5에 따로 있습니다. [출처: arxiv.org/pdf/2403.02502, Table 5]

8.5약관

2026년 11월 28일에 각 회사 공식 약관 페이지에서 확인한 조항입니다. 이 보고서는 법률 해석을 하지 않습니다.

  • 세 회사 모두 "경쟁하는 모델"의 개발을 금지합니다. 사내 전용 소형 에이전트가 이 "경쟁"에 해당하는지는 약관 문장만으로 정해지지 않습니다. 실제 적용 전에는 법무 검토가 필요합니다.
  • OpenAI의 예외는 분류·임베딩 모델과 OpenAI 파인튜닝 서비스 안의 학습에 한정됩니다. 에이전트 궤적으로 다른 생성 모델을 학습하는 경우는 예외에 들지 않습니다.
  • 위 연구들(FireAct, ToolLLM, AgentTuning, SWE-Gym, SWE-smith, CoT-Proxy)은 closed teacher를 연구 목적으로 썼습니다. 논문에 쓰였다는 사실이 서비스 적용을 허용한다는 뜻은 아닙니다.

대안은 다음과 같습니다.

  1. 공개 가중치 teacher를 씁니다. CoT-Proxy의 공개 teacher(Qwen3.6-27B)로 학습한 Qwen3-4B는 34.5%로, 행동만 쓴 closed teacher 결과(35.1%)와 비슷했습니다. 공개 모델의 라이선스 조건은 따로 확인합니다. [출처: arxiv.org/pdf/2611.33148, Table 1, Table 2]
  2. self-training으로 student가 스스로 궤적을 만들고 실행 결과로 거릅니다(3절, ETO, ActRe).
  3. 사람이 쓴 정답과 실제 실행 결과에서 궤적을 만듭니다. 정답 SQL과 실행 결과가 있는 과제에서는 teacher 없이 판정할 수 있습니다.
  4. 회사가 제공하는 파인튜닝 서비스 안에서 학습합니다. 이 경우 학습한 모델은 그 회사 플랫폼 안에서만 씁니다.

8.6텍스트-SQL·EHR 질의 에이전트에 주는 시사점

  • 도구 호출 궤적만으로도 정책은 일부 옮겨집니다. 그러나 추론을 빼면 성능 일부를 잃으므로, 궤적에 행동의 이유를 남기는 방법을 함께 씁니다. 공개 teacher의 추론 요약이 가장 효과가 컸고, 사후 설명은 그다음이었습니다(8.3절, 8.4절).
  • 요약이나 사후 설명은 student의 추론 칸 안에 넣지 않고 별도 위치에 둡니다. 추론 칸에 넣으면 student가 짧은 요약 문체를 따라 합니다(CoT-Proxy Table 5).
  • 학습 대상은 파싱한 도구 호출만 남깁니다. teacher의 보이는 설명 문장까지 학습하면 성능이 크게 떨어질 수 있습니다(CoT-Proxy Table 7).
  • 정답 궤적만 남기는 실행 결과 필터, 실패 궤적의 별도 활용, 일반 데이터나 자기 생성 데이터의 혼합을 함께 씁니다. 에이전트 데이터만 학습하면 다른 과제 성능이 무너질 수 있습니다(AgentTuning Table 5, CoT-Proxy Table 3).
  • closed model을 teacher로 쓰기 전에 약관의 경쟁 모델 조항을 확인합니다. 공개 teacher와 self-training이 약관 위험이 적은 경로입니다(8.5절).

  • PLUQ의 K 값과 self-training 단계만의 효과는 arXiv판과 ACL Anthology판 본문 전체에 없습니다. 두 판 모두 appendix가 없어 더 찾을 곳이 없습니다. 저자 코드나 추가 자료는 확인하지 않았습니다.
  • Soroush et al.(NEJM AI)의 학술지 본문과 PDF는 접근이 막혀 열지 못했습니다. 이 논문의 수치는 최종판 초록만 근거입니다.
  • Bedi et al.(JAMA)의 supplement(eTable)는 내려받기가 막혀 보지 못했습니다. 본문 수치는 PMC 본문으로 확인했습니다.
  • model collapse 논문은 Nature 게재판 본문 대신 arXiv 프리프린트 본문으로 확인했습니다. 게재판에서 수치나 실험이 바뀌었는지는 대조하지 않았습니다.
  • ReST-EM과 V-STaR의 주요 결과는 그림으로만 나와, 정확한 수치 대신 그림 번호와 본문 서술을 적었습니다.
